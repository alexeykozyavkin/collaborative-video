# Collaborative Order — Video Script v2

**Format:** deterministic 1920×1080 screencast, recorded from Dana Whitfield’s workstation.

**Core rule:** after the rewind, the camera never leaves Dana’s workstation. Customer and designer activity is shown only as incoming messages, internal notes, design-version events, and confirmations inside the Collaborative Order screen.

**Demo order:** ORD-2482 · Willow & Co. · Roll label · 60 × 40 mm · Kraft uncoated · 5,000 pcs · Due Jun 18.

## Timeline

### 0:00–0:33 — The old way
Dana receives Emma Cole’s email with the order brief and source files. The request spreads into Outlook, Teams, File Explorer, PDF viewers, prepress questions, duplicate “final” files, and production pressure.

The sequence escalates to the customer message:

> **Which version should I approve?**

Dana is left trying to establish which artwork file is actually approved.

### 0:33–0:36.5 — Rewind
The chaos visibly rewinds back to Emma’s original request. Same order, same people, same changes.

### 0:36.5–0:47 — Create one Collaborative Order
Still on Dana’s workstation.

Dana opens Customer’s Canvas and creates a new order:

1. Customer → Emma Cole
2. Product → Roll label
3. Options → 60 × 40 mm · Kraft uncoated · 5,000 pcs
4. Summary → **Create order as Draft**

The order is created in **Draft**. Creating the order does not itself contact the customer.

### 0:47–0:52 — Publish Version 1 and invite Emma
The Draft shows the task:

> **Make changes to the design, or send it as is**

Dana clicks **Send as is**.

This publishes **Version 1** from the product template and sends Emma the customer invitation. The activity feed records both events. Status becomes **Awaiting customer**.

### 0:52–0:57.4 — Dana writes to Emma
Dana types a **Public reply · customer sees it**:

> Hi Emma, Version 1 is ready. Please review the copy and size.

The message remains attached to **Version 1**. The next action is waiting on the customer.

### 0:57.4–1:00.2 — Emma replies in the same order
Without leaving Dana’s screen, an incoming customer message appears:

> **Emma Cole · On Version 1**  
> Please change the text to “No artificial flavors” and use “Sourdough Boule” as the product name.

Status becomes **In collaboration** and the next action returns to Dana.

### 1:00.2–1:06 — Dana coordinates internally
Dana switches the same composer to **Internal note · staff only** and types:

> Nora, please update the copy per Emma’s comments. Keep the 60 × 40 mm format.

The note is visually marked **Internal**. It stays in the order history, is hidden from Emma, and does not create another customer-facing thread.

### 1:06–1:08.7 — Version 2 arrives
A new activity event appears:

> **Version 2 published**  
> Nora Petrov · Designer

Version 2 becomes the current design. No switch to a designer desktop is shown.

### 1:08.7–1:14 — Dana sends Version 2 back to Emma
Dana types another public reply:

> Version 2 is ready. I’ve updated the copy and product name.

The order waits on Emma again.

### 1:14–1:16.6 — Customer approval arrives
Incoming message:

> **Emma Cole · On Version 2**  
> Looks perfect. Approved.

### 1:16.6–1:20 — Exact version is confirmed
A green event appears:

> **Emma Cole confirmed Version 2**

Status becomes **Awaiting employee confirmation**. Dana sees:

> **Your turn to confirm**

and the CTA **Confirm & submit**.

### 1:20–1:26 — Happy end
Dana confirms the same Version 2.

Status becomes **Submitted**. The activity feed records Dana’s confirmation, and the final state holds on:

> **Order agreed**  
> Customer and employee confirmed the same Version 2.

No separate customer desktop, designer desktop, preflight sequence, or production dashboard is shown in the Collaborative Order half.

# Voice-over v2

## 0:00–0:12
“A routine print request rarely stays in one place. One email becomes a thread, source files move into folders, and questions move into chat.”

## 0:12–0:25
“Then every correction creates another file. Someone asks about trim size, someone else needs the latest artwork, and ‘final’ quickly becomes ‘final approved two.’”

## 0:25–0:36.5
“By the time the customer asks which version to approve, the real problem isn’t the design. It’s the fragmented process.”

## 0:36.5–0:49
“With Collaborative Order, Dana starts the same request as one structured order. Customer, product, options, files, and the current design all stay in the same context.”

## 0:49–0:59
“She publishes Version One and invites Emma. Public replies stay with the order and with the exact design version they refer to.”

## 0:59–1:08
“When Emma asks for a change, Dana sees the feedback on Version One and can leave an internal note for her designer without opening another email or Teams thread.”

## 1:08–1:17
“Nora publishes Version Two. Dana sends it back from the same conversation, and Emma approves the revision she is actually looking at.”

## 1:17–1:26
“Customer confirmation and employee confirmation now point to the same Version Two. One order, one conversation, one agreed design.”
